# Still 0.1.25

- Fix Android running out of memory when importing successive books, including War and Peace after The Prince with Moby-Dick already in the library.
- Stream EPUB downloads directly to a temporary file and reuse the existing importer. Release unused reader caches between books and build reader data when opening a book.
- Stream saved book data and backups, avoiding large temporary JSON copies. Check for duplicates without loading another copy of the entire library.
- Preserve existing books, original files, reading positions, edits, chapters, and portable backups. No re-import is needed. Download progress, cancellation, file-size limits, and duplicate prevention remain supported.

The issue was reproduced in 0.1.24 on a 192 MiB Android app heap. With the full reader UI visible, the old build failed importing War and Peace after Moby-Dick and The Prince. The fixed build imported all three without restarting and reopened each at its saved position. War and Peace's measured import peak fell from 191 MiB to 74 MiB. These are emulator measurements; physical-phone verification remains outstanding.

Validation: 88 Android unit tests (3 optional corpus tests skipped), 40 Android reader/catalog device tests (3 optional cases skipped), the real-book successive-import regression, Android lint, native Swift/Kotlin prepared-reader and PDF/EPUB backup compatibility checks, eight release-tool tests, and a macOS build. Tests cover partial-file cleanup after failure/cancellation, atomic saves, duplicate imports, existing-book reopening, text edits, reader modes, and backup restore. The signed release build also runs Android unit tests and release lint.

Built and published from `main`. Requires Android 9 or newer. Android package: `com.stillreader.app`, version code **26**. Signed with the existing Still release key so it updates earlier release installations while preserving the library and settings.

The APK, SHA256SUMS, source commit manifest, and public signing certificate are attached to this release.
